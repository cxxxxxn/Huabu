# Working with this Space through Huabu RFS

The local usage above is generated by the installed CLI. Run it with your own compatible Node: `node "$HUABU_RFS_ENTRY" COMMAND`; on PowerShell use `node "$env:HUABU_RFS_ENTRY" COMMAND`. `HUABU_RFS_URL` and `AGENTLET_TOKEN` supply the authenticated Space connection.

Prefer direct query, download, upload and execute for deterministic Space work. Use Agent creation or prompting only when a visible conversation and open-ended interpretation are useful. Selected-node file paths identify what to download; query bounded metadata when you need to discover more. Do not infer Space geometry from a conversation preview.

Load only the workflow you need with `COMMAND --help`. Query/execute help without a type includes the live operation catalogue; `query --help TYPE` or `execute --help TYPE` includes only that operation's schema-derived contract. Do not guess fields from examples or treat a copied schema as permanently current.

For cross-command workflows, use `get-skill ID`: `layout` for structured layouts, `tasks` for durable Tasks/Runs, `agents` for full Agent control/delegation, `interactive-views` for durable sandboxed Views, and `service-config` for private in-process Service leases. These workflows use canonical operation names and HTTP resources; command help explains the CLI adaptation.

For provider work, start with `service --help`, inspect `service list`, read the selected Package with `service skill ID`, and download it with `service download ID --out-folder FOLDER`. Read its `SKILL.md` before running or modifying an optional entry; provider execution is not part of this client.

This default guide is replaced by a Space `skill.md` override when present. Live Skill Frames follow the applicable guide. Argument-free `get-skill` and global `--help` include the same Space-aware root guide with local CLI usage. Focused Skills and command help do not repeatedly append Space instructions.
