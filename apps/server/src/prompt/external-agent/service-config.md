# Using Service configuration in your own process

Use this guide when the bundled Service entry cannot perform the provider operation you need, or when you have no compatible Node runtime. This is a configuration lease workflow, not a generic provider runner or proxy.

1. Discover configured Services with authenticated `GET $HUABU_RFS_URL/services`. Select only an Agent-facing Service that has a `skill` link. Read its `GET /services/<id>/skill` and credential-free `GET /services/<id>/manifest`; use the provider documentation linked by that Skill.
2. Write a business subprocess in your available language. Inside that process, send authenticated `POST /services/<id>/lease`, using `AGENTLET_TOKEN` from its inherited environment, without putting that token in argv. Reject non-2xx HTTP responses and invalid/incoherent lease data explicitly. A successful lease contains `id`, `version`, `manifest`, and `config`; use that one coherent response for the operation, not a separately cached Manifest.
3. Consume the lease in memory and authenticate only to the intended provider. Construct the documented provider request for your business operation; do not forward the Huabu bearer credential to the provider. Respect the Service's declared configuration keys and provider endpoint rather than inventing a universal environment mapping.
4. Emit only the business result (for example artifact bytes or a bounded result description). Do not dump the lease, provider request headers, or credentials into tool output, logs, files, argv, or a global shell environment. Sanitize provider diagnostics that could echo credentials. Do not send credentials to unrelated recipients.
5. Obtain a fresh lease for a new operation when current configuration matters. A lease is a point-in-time snapshot, not a subscription or a retry/idempotency guarantee. After an ambiguous provider mutation failure, inspect provider state before deciding whether another operation is safe.

With compatible Node, the Huabu-owned SDK can perform step 2: `const { withServiceContext } = await import(process.env.HUABU_SERVICE_SDK_URL);` followed by `await withServiceContext('<id>', async lease => { /* business operation */ });`. The callback receives the coherent lease and returns your business result. Huabu provides the SDK coordinate, not a Node executable. Never import the obsolete `AGENTLET_SERVICE_SDK_URL` or silently substitute stale configuration when a lease fails.

Without Node, use your own HTTP library within the business process. Do not use a shell command that prints `POST /services/<id>/lease` into the agent transcript as an intermediate step. The optional RFS CLI deliberately has no provider execution or credential-export command; these are still the existing language-independent HTTP APIs.
