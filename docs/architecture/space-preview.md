# Space Shortcut and World

> Authoritative contract for Space Shortcut nodes, managed World entries, and the retained scene projection API.
> Last updated: 2026-10-21

## 1. Product model

A Space Shortcut retains the persisted node type `spacePreview` and target identity `targetCanvasId`. Width is fixed; the optional legacy `widthMode` field is normalized to `'fixed'`, including older `'auto'` values. Ordinary shortcuts are navigation references, not ownership relationships. A child Space uses the same compact card format for its formal entry, identified exclusively by the child's `parentSpaceId` and `parentEntryNodeId`. Its body contains only the current target name and a lightweight node-count/update-time summary when known, without a Space icon or shortcut-arrow badge. It never mounts target content or fetches a preview scene. Deleting an ordinary shortcut does not delete its target.

Ordinary shortcuts show an `ArrowUpRight` marker immediately after the target name, inheriting the name's text color, with a localized "Shortcut" tooltip and accessible label. Its SVG box follows the title's font size (`1em`) and is centered in the first title line (`1lh`), with a 4px gap and no manual vertical offset. Formal child entries and World-managed entries omit this marker. The name still clamps to two lines while the marker remains visible; the summary contains only count and update time, with no shortcut label. The marker does not change authored card width or navigation.

Space shortcuts do not participate in node preprocessing. The web queue excludes them before scheduling and ingestion-state updates, including edit-settle and unload keepalive paths; moving or resizing a shortcut therefore does not send a preprocessing POST.

World is a server-managed Canvas containing exactly one `spacePreview` for every ordinary Space in the active workspace, alongside any ordinary World-owned nodes and edges. `reconcileWorldPreviews()` owns preview membership and target identity while preserving existing preview IDs, position, size, and presentation data. Missing previews receive fresh IDs and deterministic open-grid placement; deleted targets lose their managed preview. Duplicate targets or malformed managed identities are integrity errors. Reconciliation never reuses legacy Portal IDs or geometry.

World's canvas and layer tree display only top-level entries. Nested entries and their incident edges are omitted from rendering, and nested entries are excluded from selection; persisted topology is not filtered. Hierarchy updates clear already-selected hidden entries and incident edges in CanvasPage, including while the Canvas surface is unmounted for fullscreen Preview; this transient cleanup does not schedule a save. Thus reparenting never destroys World layout, and promoting a Space restores its previous entry placement. Until target hierarchy metadata arrives, entries are withheld rather than briefly exposing all descendants. Without a saved viewport, World's initial fit waits for hierarchy metadata and the React Flow instance, then runs once against visible nodes. A metadata error releases the loading overlay without consuming the pending fit, so a successful retry can finish initialization; subsequent metadata refreshes do not reset the user's viewport. Ordinary World-owned content remains visible. Stored World references retain the existing explicit read-only tool-access policy; visibility is not authorization.

### Space ownership and lifecycle

World selection cleanup also runs when Canvas loading completes, even if hierarchy metadata arrived before the loaded nodes. Child creation recognizes eligible screen-space taps before considering flow-space rectangles, so zooming out does not turn a small touch movement into collection; Frame-only creation retains its rectangle behavior.

Each ordinary Space has at most one parent in the active Workspace. Parent ancestry must exist and cannot contain cycles; World cannot be either parent or child. Existing records without hierarchy metadata remain top-level. A new child gets a formal `spacePreview` entry in its parent. Reparenting creates a new formal entry and leaves the previous card as an ordinary shortcut; promotion clears parent metadata. Copying an entry creates only a reference because the copy's node ID is not the canonical entry ID. Ordinary card movement and Frame membership do not change ownership.

The existing canvas header combines canonical Space ancestors and the current editable Space title/menu into one breadcrumb, without a Workspace name or Home crumb. A top-level Space displays only its current title/menu. Available width determines how many ancestors are visible: the root Space and current title remain visible, middle ancestors collapse into an ordered overflow menu first, and the direct parent collapses last. Long labels truncate with full-title tooltips. There is no additional full-width navigation bar, inline management toolbar, or child-Space listing. Opening a non-owned shortcut records its source Space and Workspace in router history state; the destination header exposes a back arrow labeled with the source name. This return action sits outside the breadcrumb, immediately before the layers toggle in the header's trailing action group, with matching ghost-button sizing, subtle foreground color, hover treatment, and 16px icon. It pops that history entry, preserving the existing viewport restoration and any earlier shortcut-return chain. The source never becomes a canonical ancestor, and return state from another Workspace is ignored.

The floating header sizes to its visible breadcrumbs and adjacent controls, not the full hidden ancestry. Measurement elements stay out of document flow; a separate width-limit probe keeps the collapse budget stable as crumbs disappear and reappear on resize. Breadcrumbs use tight separator spacing and a baseline ellipsis for the ancestor menu, without a growing spacer after the current title.

Change parent derives its current parent from loaded hierarchy metadata rather than an opening-time snapshot. Until the current Space summary is ready, selection and submission are disabled. A parent conflict refreshes the metadata and resets the draft to the actual parent, leaving the dialog open for a fresh choice.

New child creation has a primary canvas toolbar button after Sketch, using shortcut `5`; both are unavailable in World. Space icons in creation controls, shortcut pickers, and node-type surfaces resolve through `NODE_ICON.spacePreview` in `config/nodeIcons.ts`, currently Layers2; card bodies do not render it. Add Space Shortcut remains in the Add Content dropdown. The child button or shortcut always arms a one-shot creation tool, regardless of the current selection. It reuses the Frame pointer gesture: a click/tap creates an empty untitled child at that flow-space position, while a rectangle collects top-level roots using Frame's 50% overlap rule, including descendants of selected Frames. An empty rectangle creates an empty child at its top-left. Both paths keep the user in the source Space without a naming dialog or automatic navigation; the new entry opens the child explicitly. Pressing `5` again, Escape, or switching tools cancels pending placement. The validated child-creation API accepts an optional finite `position`; callers that omit it retain automatic entry placement. Change parent and Delete Space live in the current Space menu and open focused dialogs. Existing save-draining and per-Space viewport persistence handle navigation.

The multi-selection toolbar exposes Collect into child Space directly; for a single selected node, the action lives in More with its shortcut hint rather than occupying a primary toolbar slot. Both use `Cmd+Option+S` on macOS and `Ctrl+Alt+S` elsewhere (S for Space). The shortcut matches physical `KeyS` as well as the text key so macOS Option-generated characters work. It ignores empty selections, editable fields, composition, repeated keydowns, and non-canvas interaction contexts; `Cmd/Ctrl+G` still groups a Frame. Collection creates an untitled owned child, retains a canonical entry at the moved roots' former top-left, preserves relative layout, and keeps the source Space open. Unsupported nodes are rejected by the existing migration service rather than silently skipped.

Home remembers Top level / All selection through the shared keyboard-accessible TabGroup below its heading; selected tabs retain their surface background on hover. A compact search field sits beside Import and New Space and wraps below the heading on narrow screens. Search matches Space names across all levels, not ancestor names or paths; results display canonical ancestry for orientation. This is a metadata search, not recursive content search.

`POST /api/canvas/:canvasId/children` creates a child; `PATCH /api/canvas/:canvasId/parent` uses `expectedParentSpaceId` to reject stale reparenting. `GET /api/canvas/:canvasId/deletion-preview` returns the owned subtree plus a membership token; `POST /api/canvas/:canvasId/delete-tree` requires that token. A changed subtree returns a conflict requiring renewed confirmation. Legacy single-Space DELETE refuses non-leaf Spaces and uses the same lifecycle path for leaves.

Confirmed deletion removes descendants before ancestors, never follows ordinary shortcuts, and removes the deleted root's formal entry from its surviving parent. It rejects represented running/busy Agent conversations before deleting anything. Failures report `deletedCanvasIds` and `remainingCanvasIds` explicitly. Generic commands, delta replay, structural PUT, and node-sidecar deletion cannot remove or retarget a live formal entry. A single entry's UI Delete action opens subtree confirmation; mixed selections or Frame deletion containing entries ask the user to delete those Spaces explicitly first. Entry deletion uses the shared node toolbar's More menu (or keyboard Delete), with no duplicate standalone delete button. Confirmation uses Common Modal with initial focus on Cancel, a root-Space summary, a bounded list of affected descendants, and a count-bearing destructive action. Short copy states irreversibility and that shortcut-only targets are kept. System lifecycle/compensation writes are trusted exceptions.

Structural saves merge omitted node identity fields with the current server record before validation. Commands, delta replay, structural PUT, and sidecar deletion compare existing shortcut IDs, types, and targets with the proposed result; unchanged identities require no hierarchy lookup. Only removed or retargeted shortcuts with syntactically valid Space IDs read their prior target through the existing Space handle and check its parent/entry metadata. Malformed dangling targets cannot identify canonical children and remain removable or retargetable without a storage lookup. This avoids Workspace-wide membership scans and does not introduce a second hierarchy cache. The check protects transitions from the authoritative prestate, not repair of externally corrupted topology.

Before local destructive command effects, the client requires settled ownership metadata for affected Space cards, including descendants of deleted Frames. Unknown ownership blocks the change, starts a metadata refresh, and asks the user to retry; it never permits partial sidecar deletion. Received Space-card insertions invalidate/refetch metadata before exposing the new nodes. Undo and redo validate restored identities before consuming history or scheduling sidecar effects: a snapshot that would remove or retarget a live child entry is refused with an explicit lifecycle-action message, while geometry undo/redo remains available.

Child creation and reparenting defer entry-insertion publication until the parent metadata write settles, using the same deferred executor publication as Space Move. A failed parent write still publishes the retained card after settling, so clients refresh against the resulting authoritative ownership rather than caching the pre-write parent. The operation continues to report failure; publication does not turn an incomplete attachment into success.

The move-success Open destination action keeps fullscreen Preview active. In fullscreen mode it consumes the one-shot destination focus intent without selecting nodes or fitting the Canvas viewport; it does not replay that intent on leaving fullscreen. Destination data loading, realtime synchronization, and the Layers panel continue normally.

Partial subtree deletion failures reconcile the server-confirmed deleted IDs from the shared error-details contract against the confirmed preview. Deleted Preview persistence is removed, affected lists refresh, and a deleted current Space navigates to Home. The failure remains visible in a toast and, where still mounted, the dialog; a deleted root does not offer a retry that can only return 404. Partial completion is never reported as full success.

Successful deletion rechecks the captured Workspace after awaiting the metadata refresh, before invoking navigation callbacks. An old dialog's asynchronous completion cannot navigate a newly active Workspace.

Hierarchy operations share a process-local serialization queue and hold a Workspace-operation lease. Canvas mutexes guard entry creation and deletion alongside content writes, and the existing per-Space storage deletion fence protects cleanup. This is not a distributed transaction or crash-atomic multi-Space mutation; failed child attachment retains the created Space and reports its identity, and a refresh resolves uncertain ownership writes. No directory relocation or automatic Prompt/Memory inheritance follows ownership.

World slot allocation reserves the shared maximum compact height (138 canvas units) for every existing shortcut, regardless of width mode or a legacy persisted height. This occupancy calculation does not rewrite stored geometry; ordinary non-shortcut nodes retain their authored height for collision avoidance.

If a reconciliation command reports that it was not applied, reconciliation re-reads World and membership once. It succeeds only if that fresh plan requires no changes for the same World, allowing a concurrent writer to have already completed a stale-preview deletion. Outstanding work, malformed identities, and executor exceptions remain errors; this does not add automatic retries or a transaction spanning planning and execution.

Legacy `canvasRef`, `frameRef`, and `nodeRef` nodes, Portal/Pin renderers, the `SET_PORTAL_NODE_PINS` command, and `GET /api/canvas/:canvasId/references` are retired, not compatibility APIs. The shared `stripLegacyPortalTopology()` helper ignores those three exact node types and their incident edges at read/load, clipboard, and history-restore boundaries. Ordinary children survive: a child directly parented by an ignored node is detached to the root with its position rebased through the original ancestor chain. This is an in-memory projection with no disk cleanup, sidecar deletion, or legacy-to-preview migration; normal later saves may omit ignored topology. See [canvas-storage.md](./canvas-storage.md) for the storage boundary.

Only system reconciliation creates managed World previews. UI and Agent mutations cannot repoint them, change their type, or delete them while their target remains a live Space, including through ancestor deletion or a reparent-then-delete batch. Missing-target previews remain removable. Users may move, resize, and parent previews under ordinary Frames; a preview is not itself a Container and owns no source-node children.

Write boundaries use the canonical registries, not a retired-type blacklist: every command discriminator must be an own entry in the shared engine's full `COMMAND_META` registry, including UI-only commands. Before persistence, command results, delta replay (including revert), and full-state PUT validate explicitly supplied node `type` and optional `data.type` against `CANVAS_NODE_TYPES`; omitted discriminators remain accepted by the loose full-state contract. Unsupported explicit types are rejected on writes, whereas `stripLegacyPortalTopology()` still preserves unrelated unknown node types on reads/imports rather than silently stripping them. Agent media normalization checks all create-node discriminators before importing bytes; other command payloads retain normal handler rejection/no-op behavior and final topology validation.

World-owned conversations may use `spacePreview.targetCanvasId` from the World outline for explicit read-only tool access. The server requires exactly one matching canonical preview and a readable live ordinary target Space. This does not grant cross-Space writes or source conversation presentation: opening a source Question requires entering its Space, not interacting with the projected scene.

## 2. Retained scene projection boundary

The following server API and shared wire contract remain available, but the production shortcut does not use them. The old web scene client, SVG viewport, scene cache, and local pan/zoom persistence implementation have been removed. A PNG cover generator, thumbnail storage, and snapshot invalidation are not required for this design. Existing browser-local preview viewport records are left untouched but are no longer read or written.

`GET /api/canvas/:canvasId/preview-scene` accepts only an ordinary Space in the active workspace. The server reads the target through the storage ports — `space(canvasId).read()` for topology, `nodes.list()` for node records — and converts the result into the shared zod contract in `packages/shared/src/types/api/space-preview.ts`. Missing targets return `404`; a target whose Space record cannot be produced, or whose topology is not the expected shape, returns `422`. Node records are read the one lenient way the port defines: a record that cannot be produced is omitted and the projection falls back to topology data, and a record broken by hand recovers the same way it does when its own Space is opened. A single damaged sidecar therefore renders leniently rather than failing the whole preview, which is the behaviour of the Space's own view.

The response contains identity, title, Canvas version, absolute node geometry, safe visual kinds, whitespace-normalized labels, bounded plain-text excerpts for Note and Text nodes, bounded Image source references, eligible edges, scene bounds, and explicit truncation flags. Markdown is flattened before projection; inline `data:` and renderer-local `blob:` image sources are excluded. The response never includes complete rich-editor state, prompts, chat and Agent state, Interactive View state, artifact bytes, handles, selection, or mutation metadata.

Projection keeps deterministic source order and is bounded to 250 nodes, 400 edges, and 1 MiB serialized JSON. Source `spacePreview` nodes become inert `nested-preview` placeholders, so projection has exactly one live scene depth and cannot recurse through self-reference or cycles. Retired Portal/Pin topology is already excluded by the composed Space read.

## 3. Web rendering and freshness

The production renderer reuses `NodeWrapper`, the shared 3px boundary, radius, Note surface/accent treatment, 16px content padding, and 28px/500 card-title typography. The shortcut is flat, including during hover and drag. Titles wrap to at most two lines and expose their full value on hover. The card has no icon column or reserved icon gap. A muted 16px/400 metadata row sits 4px below the title. Loading, missing-target, and error states use visible status text instead of an icon, with failures using the warning color. The summary stays on one line with ellipsis at narrow widths and exposes the full count and exact local timestamp on hover and through an accessible label. There is no permanent Open button, URL, cover, or local viewport.

Target identity, title, node count, and update time come from the workspace's shared Space list metadata, not persisted labels or scene responses. Loading, ready, missing, and request-error states are distinct; an untitled live Space remains ready. Duplicate shortcuts share list requests. Entry and browser focus refresh metadata; a successful local rename updates the title immediately and refreshes its summary. Requests from a previous workspace cannot replace the current workspace's metadata. Failed reads are surfaced and can be retried from the selected shortcut toolbar. No per-node polling or target SSE subscription is needed.

Node count uses the server list's direct topology count: all target Space nodes, including Frames, their children, and Space Shortcuts, without recursively counting referenced Spaces. Zero is explicitly shown as an empty Space; an unknown count is omitted, never fabricated as zero. Update time is the Space record's `updatedAt`, which includes persisted layout/structure changes and is not a content-only or last-visited timestamp. Unknown/zero timestamps are omitted. Relative ages are localized and advance on one shared minute timer while summaries are mounted; this timer does not fetch metadata. Summaries are snapshots refreshed on entry/focus and explicit local move/rename, not real-time subscriptions to inactive target Spaces.

A successful cross-Space move immediately publishes the destination ID and server-confirmed title into the same workspace cache, for both new and existing destinations, and invalidates/refetches summaries for both source and destination. An older in-flight list cannot erase that confirmed entry or restore invalidated counts; mutations during a list request coalesce into one trailing fresh read. A response arriving after a workspace switch cannot populate the new workspace or trigger an old-workspace trailing read. Thus a newly created breadcrumb is usable before its summary arrives, without a focus change or page reload.

Request activity is separate from target availability: previously confirmed targets remain ready during background refresh, including a failed refresh. Refresh errors still show a warning and Retry action; they do not silently disappear or disable known targets. Unknown targets remain loading until the request settles, and a successful list that omits a target marks it missing and disables navigation. Workspace switching always blocks entry, regardless of cached metadata.

Invalidating a summary clears counts and timestamps but retains last-confirmed parent and entry identity. An older in-flight list cannot replace that retained hierarchy for invalidated IDs; a trailing read must settle before destructive ownership checks resume. A failed post-rename refresh therefore preserves World visibility and breadcrumbs without presenting stale counts. A successful fresh list still removes metadata for genuinely deleted targets.

New shortcuts use a fixed 360-unit default width. Widths have a 240-unit minimum and no shortcut-specific upper limit. The shared `FloatingToolbar.SizePicker` renders only W, with no automatic-width toggle; both the real node toolbar and design playground use it, with no Space-specific size form. Width edits use the shared picker commit rules (Enter/blur, rounding, minimum clamping, and invalid-draft restoration). Side resizing, command creation/geometry, and load normalization preserve values above 720 instead of clipping them. Height is renderer-owned and follows one or two title lines plus the summary when available; font metrics do not scale with width. Toolbar width commits and side resizing use the existing geometry/history commands. Width survives target renames, summary updates, undo/redo, and reload. Shared sizing constants provide nominal 360 by 102 headless geometry; new World slots reserve 360 by 138 and existing entries reserve their saved width.

Loading a legacy preview preserves its ID, target, position, parent, edges, and width subject to the 240-unit minimum, marks it fixed regardless of its previous width mode, and releases its old pinned height. No title measurement runs, including for an already-loaded legacy automatic card. There is no destructive migration or immediate disk rewrite; ordinary later saves persist the normalized shape.

## 4. Interaction and accessibility

The shared node shell owns selection, movement, connection handles, and canvas gestures. There is no nested wheel/pan/key handler. Single click selects; double click, Enter on the sole selected shortcut, or the selected toolbar's Open Space action enters the target through the router. All three entry paths use the same ready-target guard. Missing targets and failed initial lookups remain selectable and resizable, with warning status and a disabled Open action; a failed background refresh of a known target warns without disabling entry.

The toolbar offers accent, width, Open Space, and ordinary node actions. Width input validates integers explicitly; no height input or vertical/corner resize is exposed. The real canvas uses the existing left/right resize controls and undo/redo infrastructure. Title tooltips, visible accessible status text, labelled controls, and input errors remain available to keyboard and assistive-technology users.

Gesture-driven zoom-through remains deferred; viewport zoom, responsive layout, and shortcut resize never navigate.

Ordinary Spaces expose Add Space Shortcut from the Canvas toolbar's Add Content dropdown. World omits this action because its shortcut membership is server-managed. The action opens a compact searchable tree popover above the persistent Add Content trigger, reusing `SpacePicker` with Move to another Space rather than a separate flat modal list. Canonical parent metadata determines the branches; the current Space stays disabled but expandable, and World is omitted. Expanding never creates a card, search includes collapsed descendants and ancestor paths, and Escape restores trigger focus. Choosing a target creates only an ordinary shortcut in the current Space, with no navigation or ownership change; ancestors and descendants remain valid targets. Loading/error/empty feedback is explicit, and closing or changing Space/Workspace cancels stale list publication.

Move to another Space opens a compact existing-destination hierarchy, excluding World. Rows use normal-weight single-line labels, the shared Space icon, separate expand chevrons, and indentation. The current Space remains visible but disabled so its children can be browsed, with its ancestor path expanded initially. Search finds collapsed descendants by name and canonical ancestor path, showing the latter inline to disambiguate matches. Selecting a destination immediately submits; expanding a row never moves content. There is no creation/name step, ownership checkbox, source-shortcut checkbox, or second confirmation button. Up/Down navigate results, Left/Right collapse/expand branches, loading/error/empty states remain explicit, and Escape restores trigger focus. The footer shows the captured selection count and only warns about boundary edges when present. A pending move locks the chooser and captures its original selection. Existing-destination moves create no source shortcut and never reparent the destination. The underlying API retains its optional ordinary source-shortcut and top-level creation capabilities for other callers.

Selections may mix ordinary nodes, Frames, child Space entries, and ordinary Space shortcuts; selecting a Space card no longer hides collection or migration actions. Frame descendants participate even when not individually selected. An ordinary shortcut moves only its card, preserving its target and ownership. Moving a canonical child entry updates that child's `parentSpaceId` and `parentEntryNodeId` to the destination and remapped entry ID without moving the child's contents or changing its descendants. The chooser disables each moved child's own Space and descendants, and the server independently rejects these cyclic destinations with `MOVE_HIERARCHY_CYCLE` before mutation. A shortcut alone does not impose this restriction.

Collection and existing-destination moves share save draining, error mapping, duplicate-request protection, metadata publication, and stale source/Workspace guards. Success keeps the source Space and viewport in place; realtime synchronization applies the server changes. A dismissible success toast offers Open destination for eight seconds rather than navigating automatically. Explicitly using that action carries a one-shot focus intent containing the server-returned destination root IDs. After loading and React Flow readiness, the page selects and fits those roots with zoom capped at 100% and focuses the Canvas rather than an editor, then consumes only the focus intent. Return-to-source history remains available in the header. A response received after leaving the source never redirects the user; Workspace changes also prevent stale metadata publication and invalidate the toast's navigation action. The existing move transaction, Agent restrictions, boundary-edge removal, and compensation remain authoritative. The hierarchy lock serializes ownership operations, while Canvas mutexes cover source, destination, and direct source children because disk parent updates rewrite each child's Space record. Ownership updates are recorded before writing and compensated in reverse order before scene rollback, including attachment of a newly collected child. Failed ownership restoration reports `MOVE_OUTCOME_UNKNOWN` and retains the destination rather than risking destructive cleanup.

Entering or returning to a Space uses a 240ms ease-out opacity entrance on the React Flow surface, starting only after initial viewport restoration/fitting has released its visibility gate. The animation does not run on a hidden canvas while its loading overlay is visible. Header and side panels do not animate. This reuses the existing readiness state without delaying navigation, retaining an old interactive canvas, or adding camera zoom. Loading and unavailable-Space feedback remain unchanged. The entrance is disabled under `prefers-reduced-motion: reduce`.

## Development design comparison

The development-only `/playground/space-previews` route demonstrates a compact Space Shortcut instead of a snapshot card. Two instances share a locally editable target title, with one initially unselected and the other selected. Each instance contains a title clamped to two lines and the production summary component using local node-count/update-time fixtures; there is no icon, cover, snapshot request, internal viewport, height control, URL, or permanent navigation arrow. The title follows `NODE_TYPOGRAPHY.cardTitle` (28 canvas units, weight 500), with `NODE_CONTENT_SPACING`, the shared `nodeMetricsForSize` radius, `nodeBoundaryForAccent` 3px boundary, and `noteSurfaceStyle` surface/accent treatment. Summary typography and the 4px title/summary gap match production. No custom neutral border color or card shadow is introduced.

Single click or Space selects the shortcut; double click or Enter opens a labelled local destination demonstration; Escape deselects it. Title and summary stay inside the button so they do not interrupt gestures. Only selected shortcuts display the common floating toolbar with the reused specimen type/drag handle, accent picker, width settings, and Open Space action. An unavailable target adds an explicit status and blocks toolbar, double-click, and Enter entry without preventing selection. Title edits update both instances; accent, width mode, and position stay independent.

Width starts at 360 canvas units and stays fixed across title and summary changes. The width popover reuses Common `FloatingToolbar.SizePicker` with a 240-unit minimum and no custom-width maximum, without exposing height or an automatic-width toggle. Height follows one or two title lines and the summary when available, without changing font metrics. Left/right grips support pointer capture, opposite-edge anchoring, 16-unit arrow-key adjustments, and rollback on pointer cancellation or Escape. The demonstration stage bounds visible width and grip movement without discarding larger widths entered in the form; this stage constraint does not apply to the production canvas. A ResizeObserver reports actual dimensions below each specimen. The page includes the design rationale, experimental limits, an interaction checklist, and explicit production-integration exclusions.

The experiment shares the production width form and bounds, but does not mount a nested viewport, persist state, fetch real Spaces, or navigate to real targets. Production now uses the shortcut design described above; managed World membership remains unchanged. Demo-only keyboard side resizing and small-screen stage constraints are not production canvas contracts. The page remains linked from `/playground/node-toolbars` and links to the production-metric node design gallery.

The earlier six-node cover fixture, generated PNG, and special snapshot-source query mode are retired. The playground now demonstrates only the shortcut.
